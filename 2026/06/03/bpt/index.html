BPT

Obsidian

简介

提出了一个高效的mesh 表示：Blocked and Patchified Tokenization(BPT)

BPT

Preliminary

给定一个三角网格 M=(f1,f2,…,fn) ，可以这样表示

fi=(vi1,vi2,vi3)=(xi1,yi1,yi1,…)

端点被按照 z−y−x 顺序排序，然后面按照最小的端点序号来排序。

Block-wise Indexing

Naive Indexing

最基本的想法是：把 3D 坐标 (xi,yi,zi) 变成一个标量序号 Ii 。使用7-bit 量化( r=128 )，每一维度坐标变成 [0,r−1] ，那么 Ii 就变成 [0,r3−1] 。这会带来 transformer 无法承受的大小。

Indexing in each block

作者把每个维度坐标系变成 B 段，每一段长度为 O 。那么对于一个端点 vi=(xi,yi,zi) ，block-wise 标号 (bi,oi) 可以这样计算：

bi=(xi|O)B2+(yi|O)⋅B+zi|Ooi=(xi%O)O2+(yi%O)O+zi%O

这里 | 表示整除， % 表示取模。

Block indexes compression

因为坐标是按照 z−y−x 顺序排序的，那么下一个预测的端点很可能处于同一个 block 里面。因此我们可以做一个结合：

(vi,vi+1,…,vn)=(bi,oi,oi+1,…,on)

其中 vi,…,vn 处于同一个 block。这样极大的压缩了序列。

Patchified Aggregation

在普通的 mesh 表示中，每个端点会出现很多次造成冗余。这里作者提出可以把连接到同一个端点的面聚合起来，形成一个 patch。

Next Patch Prediction

在把mesh 变成 patch 的关键一步是寻找 patch 的中心顶点。首先我们把整个排序后的面序列初始化为unvisited。然后我们选择第一个未访问的面，然后把这个面的和最多未访问的面连接的端点标记为 patch 中心。最后，所有和中心端点连接的面被聚合起来形成一个 patch：

Pc=(vc,v1,v2),(vc,v2,v3),…,(vc,vn−1,vn)=(vc,v1,…,vn)

然后把这些面标记为已访问。重复这个过程直到所有面都被访问。

Seperate patches with dual-block indexes

一个直觉上对于标记一个patch 的开始和结束的方式是加入特殊的 token。但是这样会带来序列的复杂性。这里作者使用对偶 block 序号来表示。具体地说，作者给 vc 和 v1,…n 创建了两个 block index vocabulary，但是 offset vocabulary 是共享的。

Pc=(bc′,oc,b1,o1,…,bn,on)

Mesh Generation based on BPT

这里使用标准自回归 transformer，参数记为 θ 。使用 cross-attention作为条件。

L(θ)=∏i=1|P|p(pi|p1:i−1,c;θ)

Image to Mesh

使用 DINO 来提取 feature，注入点云生成模型。
