OctFormer

Obsidian

简介

OctFormer 的提出主要是为了解决传统基于点云的 transformer 的复杂度问题。主要的 block 是一个 octree attention。为了拥有线性复杂度，作者把点云进行分组，生成不规则的窗口，但同时保证每个窗口内点的数量一致。最后可以直接使用 pytorch 的 transformer。观察到建立 Octree 之后节点是以 z-order 排列的（基于 shuffle key），用同样的顺序存储 feature张量。然后在添加一点 0 作为 padding 之后，可以直接通过张量 reshape 来做好 partition。为了进一步增加感受野，作者引入了dilated attention。这可以轻松使用 reshape 和 transpose 来进行。

基于Octree 的transformer


给定一个点云，我们首先做正则化，缩放到一个合适的比例然后建立 octree。初始的 feature 包括平均点位置，颜色，和法向量（如果有的话），它们存放在叶子节点里。之后这些 feature 被送到一个 embedding 模块并被降采样和投影到高维空间上。最后就可以经过重复的OctFormer Block和降采样来产生等级化的 feature。

Octree Attention

把输入记作 X∈RN×C ，其中 N 为空间数，C 是 channel 数。 Wq,Wk,WD∈RC×D

Attention(X)=softmax((XWq)(XWk)TD)(XWD)

OctFormer 默认使用多头注意力。下面用注意力代指多头注意力。
该式子的计算复杂度为 O(n2) ，当 n 过大时显然不可接受。我们开始划分窗口。设一个局部窗口内的点数为 K ，则window attention的计算复杂度为 O(K2⋅NK) ，是 N 线性的。一种朴素的想法是直接划分成两两不交的立方体。但是不同立方体内的点个数差距太大，不能并行。

注意到，注意力机制是通过加权平均 softmax 的方式收集 feature 的，我们可以发现 attention 是对窗口形状不敏感的。事实上，作者通过在 ViT 上面对每一个 patch 做形状的遮盖，发现最终的训练结果几乎没有明显下降。因此并没有必要限制窗口的形状。这让 gpu 高效计算成为可能。

Octree

Octree 的构建可以参考上一篇文章。最后构建出来的同一层的相邻节点在内存中的排布具有连续性。

Octree Attention

我们在构建 Octree 的时候，把每一层的 feature 都放在一个张量里面，按照 key 的顺序。我们把这个张量记作 X,(N,C) 。我们首先做一个0-padding 产生一个新的张量 X^ 形状 (N^,C) ，其中 N^ 是可以被点数 K 整除的。我们通常把 K 设为 32。然后我们把它 reshape 到 (B,K,C) ，其中 N^=BK 。这样我们就可以分别并行的对这 B 个 window 做 attention。
虽然这样可以加速计算，但是会造成感受野变小。作者引入了 dilated octree attention。我们把dilation记作 D ，如果为 1 ，那么是 trivial 的。否则，我们把 X^ 变形到 (B^,K,D,C) ，其中 N^=B^KD 然后我们把它给 transpose 到 (B^,D,K,C) 然后最后把前俩个维度给 flatten掉，变成 (B,K,C) 。

Positional Encoding

把最大窗口尺度记作 W ，那么如果朴素地推广relative positional bias需要参数是 H×(2W−1)3 ，其中 H 是头数。而在 octformer 中，dilated 大的时候 W 至少是 50，极大的增加了参数的数量。因此采用conditional positional encoding(CPE)。具体的，我们使用 O-CNN和 batchnorm：

X=X+batch_norm(depth_wise_conv(X))
