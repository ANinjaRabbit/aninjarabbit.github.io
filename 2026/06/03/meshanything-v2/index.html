meshanything v2

Obsidian

简介

主要是使用Adjacent Mesh Tokenization(AMT)对MeshAnything 进行了改进。

AMT

以往的面 tokenization 是每个面用三个顶点表示，而使用 AMT 可以平均下来几乎只用一个顶点表示一个面。我们首先看一下以往的方法。
给定 Mesh M ，顶点首先按照 z−y−x 的顺序升序排列。然后面使用它们最小的端点序号来排序：

M:=(f1,…,fN)

然后对于每一个 fi

fi:=(vi1,vi2,vi3)

注意这里的三个顶点的顺序是经过排序了的。
代入：

M:=((v11,v12,v13),..,(vN1,vN2,vN3)=SeqV)

因为经过了排序，这里的 SeqV 是唯一的，且长度是面数的三倍。这里显然有很多冗余信息。
作者提出了 AMT：


理想情况&符号用的比较少，那么序列长度就可以缩短为 13 。但是总会有极端情况。然而考虑到数据集都是 Artist-created Mesh，拓扑关系比较好，所以获得的收益还是比较大的。

Vertices Swap

考虑两个面

f1=(v1,v2,v3),f2=(v1,v3,v4)

假如说首先把 f1 放到了序列里，理论上这里可以直接加一个 v4 来表示第二个面，但是由于最后两个toekn是 v2,v3 ，所以按照原来的算法并不能。这里作者加入了一个$符号来交换端点。如果$在一个端点的前面，这表示下一个面是由上一个面的第一个和第三个端点形成的。例如说 (v1,v2,v3,$,v4) 表示 mesh 由 (v1,v2,v3) 和 (v1,v3,v4) 形成。
加入这个操作可能会带来序列学习的困难性，但是作者经过实验发现并不明显。

MeshAnything v2

和上一代一样，作者希望学习分布： p(M|S) ，这里M代表 AM，S 代表 3D 形状条件（例如点云）
v2 和上一代一样使用点云作为形状条件输入 S 。仍然适用数据对 (M,S) 。为了把 S 给输入到 transformer，首先使用预训练点云编码器把 S 变成固定长度的token序列 TS ，然后把它作为前缀。然后把 Mesh 变成 mesh token 序列 TM 放在 TS 后面。在训练完了之后，就输入 TS 然后自回归生成 TM ，然后解码得到M。这里使用 AMT。并且作者抛弃了 VQ-VAE，直接使用 SeqV 离散的坐标来作为 token。这里作者除了使用绝对坐标编码，也加入了针对 AMT 的位置编码：用三个点表示一个面时，给三个顶点加入一个特别的编码；用一个点表示一个面时，加一个不同的编码。

Face Count Condition

有些应用会要求控制大概的面数。这里作者首先初始化一个embedding book，大小等于允许的最大面数。基于当前 mesh 中的面数，我们找对应的 embedding 然后把它放在点云 prefix 的后面来表示面数。训练的时候，会加上一个扰动防止过拟合。同时会有 0.1 概率丢弃条件来提升鲁棒性。

Masking Invalid Predictions

在生成的时候，有时候会出现不合理的预测。这时候就会 mask 掉。比如说在 & 后面重新用三个端点生成三角形的时候，就会保证一定要生成三个端点再做其他的动作。
